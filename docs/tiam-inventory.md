# اتصال موجودی تیام در هاست اشتراکی

PHP هاست اشتراکی نمی‌تواند L2TP/IPSec ایجاد کند. مسیر SQL از یک ایجنت خروجی روی سیستم ویندوزی/لینوکسیِ تحت کنترل شما استفاده می‌کند. ایجنت SQL را از مسیر شبکهٔ فعلی همان سیستم اجرا می‌کند؛ مدیریت VPN توسط ایجنت اختیاری است و با HTTPS به سایت متصل می‌شود؛ پورت ورودی جدید یا انتشار SQL در اینترنت لازم نیست.

## تنظیم هر پروژه

در تنظیمات پروژه، «دریافت موجودی تیام از SQL Server» را باز کنید:

1. سرور، پورت، دیتابیس، schema و نام ویو را وارد کنید. مثلاً سرور `192.168.2.215`، دیتابیس `SplandDB` و ویو `Factinventory`؛ این‌ها فقط مثال هستند و برای هر پروژه جدا تنظیم می‌شوند. کاربر SQL باید فقط اجازهٔ SELECT روی ویوی مورد نظر داشته باشد.
2. مشخصات VPN و رمز SQL را در فرم همان پروژه وارد کنید. رمز خالی یعنی حفظ مقدار قبلی؛ رمزها داخل HTML یا لاگ برگردانده نمی‌شوند. کلید ایجنت را تولید، در سیستم اجرای ایجنت نگهداری و تنظیمات را ذخیره کنید. سایت فقط هش کلید ایجنت را ذخیره می‌کند.
3. ایجنت را اجرا کنید و «تست VPN» و سپس «تست اتصال SQL و نمایش ستون‌ها» را بزنید. تست ویو فقط پنج ردیف و نام ستون‌ها را می‌خواند؛ هیچ محصولی تغییر نمی‌کند.
4. نام ستون‌های کد کالا، نام، موجودی، سایز، رنگ، انبار، قیمت و مدل مادر را از نتیجهٔ واقعی وارد کنید. کد، نام و موجودی الزامی هستند. واحد قیمت ریال/تومان صریح است. کد مدل مادر برای حفظ هویت محصول هنگام تغییر نام مفید است.
5. «دریافت و پیش‌نمایش» را بزنید و تغییرات را بررسی و تأیید کنید. پیش‌نمایش شامل تعداد جدید/تغییریافته/بدون تغییر/غایب، قبل و بعد موجودی، سایزها و واریانت‌هاست؛ حداکثر ۱۰۰ تغییر نمایش داده می‌شود. تا تأیید هیچ محصولی نوشته نمی‌شود. پیش‌نمایش ۱۵ دقیقه اعتبار دارد و اگر داده یا تنظیمات عوض شود قابل اعمال نیست.
6. همگام‌سازی روزانه را با ساعت دلخواه، مثلاً ۱۲:۰۰ به وقت تهران، فعال کنید. ایجنت باید روشن بماند. اجرای روزانه به بازدید سایت وابسته نیست و فقط پس از اولین تأیید موفقِ همان تنظیمات و نگاشت مجاز است.

تغییر اتصال یا نگاشت، تأیید قبلی را باطل می‌کند. عدم اتصال، ردیف تکراری، موجودی نامعتبر یا پاسخ خالی دادهٔ نمونه ایجاد نمی‌کند و موجودی را تغییر نمی‌دهد. بعد از شکست زمان‌بندی، تلاش خودکار آن روز تکرار نمی‌شود؛ تست یا پیش‌نمایش دستی قابل اجرا است. «آخرین وضعیت و لاگ ایجنت» برای مشاهدهٔ نتیجهٔ آخرین کار است. صف و پیش‌نمایش در مسیر خصوصی temp یا `TIAM_STATE_DIR` نگهداری می‌شوند؛ روی هاست چندنودی باید این مسیر بین پردازش‌ها مشترک و خصوصی باشد.

کالاها طبق نام/مدل و رنگ گروه‌بندی می‌شوند؛ SKU هر سایز حفظ و موجودی انبارها تجمیع می‌شود. توضیحات و تصاویر موجود حفظ می‌شوند. کالای غایب از پاسخ به‌صورت پیش‌فرض صفر نمی‌شود؛ گزینهٔ «صفرکردن غایب‌ها» را فقط برای ویوی اسنپ‌شات کامل روشن کنید. ردیف‌های تکراریِ کالا/رنگ/سایز/انبار رد می‌شوند؛ اگر ویو تراکنشی است ابتدا آن را به موجودی تجمیعی تبدیل کنید.

## اجرای ایجنت

نیازمندی‌ها: Python 3.9+، `pyodbc` و **Microsoft ODBC Driver 18 for SQL Server**. نصب درایور از مستندات رسمی مایکروسافت:

https://learn.microsoft.com/sql/connect/odbc/download-odbc-driver-for-sql-server

وابستگی پایتون را نصب کنید: `python -m pip install pyodbc`.

این متغیرها را در محیط خصوصی کاربر/سرویس ایجنت تنظیم کنید:

- `TIAM_PANEL_URL`: آدرس HTTPS مانند `https://maarksho.com/panel/tiam_inventory.php`
- `TIAM_PROJECT_ID`: شناسهٔ همان پروژه
- `TIAM_AGENT_TOKEN`: کلید تولیدشده برای همان پروژه؛ آن را در مخزن یا لاگ نگذارید.

اجرای دائم: `python tiam_inventory_agent.py`. ایجنت هر ۳۰ ثانیه صف را بررسی می‌کند. اجرای تک‌مرحله‌ای با `--once` برای Windows Task Scheduler یا cron در سیستم ایجنت پشتیبانی می‌شود. برای هر پروژه یک فرایند/کار مستقل با متغیرهای خودش اجرا کنید. سایت کلید اشتباه پروژهٔ دیگر را رد می‌کند.

در ویندوز، ایجنت با VPN Client خود سیستم یک پروفایل L2TP/IPSec مستقل می‌سازد، وصل می‌شود و مسیر /32 سرور SQL را اضافه می‌کند. در این حالت آدرس SQL باید IPv4 باشد. خطای VPN و دسترسی TCP، خطای احراز هویت SQL و خطای SELECT جدا در مراحل گزارش می‌شوند؛ باز شدن سوکت UDP به‌تنهایی موفقیت VPN نیست.

در لینوکس، مدیر سیستم باید یک سرویس مستقل L2TP/IPSec مانند `maarksho-tiam-vpn@project1.service` را با مشخصات همان پروژه و مسیر SQL از قبل پیکربندی کند. نام سرویس در تنظیمات پروژه وارد می‌شود. کاربر ایجنت باید فقط اجازهٔ `sudo -n systemctl start` برای همان سرویس را داشته باشد. ایجنت سرویس را شروع و وضعیت و دسترسی واقعی به پورت SQL را بررسی می‌کند؛ ساخت یا تغییر تنظیمات privileged VPN از PHP انجام نمی‌شود. تغییر رمز VPN لینوکسی باید در تنظیمات سرویس محلی نیز اعمال شود.

TLS در HTTPS و SQL فعال است. گواهی SQL باید مورد اعتماد سیستم ایجنت باشد؛ اگر نام گواهی با IP متفاوت است، «نام سرور مطابق گواهی TLS» را تنظیم کنید. بررسی گواهی را غیرفعال نکنید.

لاگ‌ها شامل مراحل، زمان، وضعیت و SQLSTATE امن هستند؛ رمزها، PSK، کلید ایجنت، DSN و متن خام خطای درایور ثبت نمی‌شوند. محدودیت فعلی ۵۰۰۰۰ ردیف و ۸ مگابایت برای هر اسنپ‌شات است؛ پاسخ بزرگ‌تر ناقص اعمال نمی‌شود. مسیر REST قدیمی باقی مانده ولی دادهٔ ساختگی و تأیید ساختگی اتصال از آن حذف شده است؛ روشن‌کردن زمان‌بندی SQL، زمان‌بندی قدیمی همان پروژه را خاموش می‌کند.

## اعتبارسنجی

- `php tests/tiam_inventory.php`
- `python -m unittest discover -s tests -p 'test_tiam_inventory_agent.py'`

تست‌ها از دادهٔ آزمایشی استفاده می‌کنند؛ موفقیتشان اثبات اتصال زنده به VPN یا دیتابیس شما نیست.

## درخواست معطل و تشخیص ارتباط ایجنت

حالت `queued` یعنی درخواست هنوز توسط ایجنت دریافت نشده است؛ این حالت به معنی اجرای VPN یا SQL نیست. حالت `running` یعنی درخواست به ایجنت تحویل شده و پنل منتظر نتیجه است. در تنظیمات، وضعیت فعلی و زمان آخرین درخواست معتبر ایجنت به وقت تهران نشان داده می‌شود. ارتباط ثبت‌شده در ۹۰ ثانیهٔ اخیر فقط ارتباط HTTPS با پنل را تأیید می‌کند؛ موفقیت VPN و SQL باید از لاگ تست مربوط بررسی شود. عملیات طولانی ممکن است بدون poll جدید ادامه داشته باشد.

کلیک تکراری روی همان تست، توسط همان نشست، درخواست جدید نمی‌سازد و همان درخواست را پیگیری می‌کند. انتخاب تست دیگری هنگام وجود کار فعال، وضعیت درخواست قبلی را نمایش می‌دهد. «آخرین وضعیت و لاگ ایجنت» نیز فقط وضعیت را می‌خواند. درخواست‌های صف/اجرا بعد از ۱۵ دقیقه منقضی می‌شوند؛ پیش‌نمایش همچنان محدودیت ۱۵ دقیقه‌ای دارد.

برای درخواست معطل، ابتدا آخرین وضعیت را دریافت کنید و «لغو درخواست معطل / جاری» را بزنید. ایجادکنندهٔ درخواست و مدیر پروژه/مدیر سراسری با مجوز استفاده از تنظیمات می‌توانند آن را لغو کنند. شناسهٔ درخواست باید دقیقاً با کار فعلی منطبق باشد؛ درخواست قدیمی نمی‌تواند کار جدید را لغو کند. نتیجهٔ دیررس درخواست لغوشده رد می‌شود و قابل اعمال نیست. لغو در پنل، دستور سیستم‌عامل یا VPN در حال اجرا روی ویندوز را فوراً متوقف نمی‌کند؛ برای توقف ایجنت از Ctrl+C استفاده کنید. بعد از توقف پردازش قبلی، ایجنت را دوباره اجرا و تست جدید ایجاد کنید.

نسخهٔ جدید ایجنت در آغاز `Agent started` و پس از پاسخ معتبر پنل `panel connected; waiting for a queued job` را چاپ می‌کند. هنگام تحویل کار `job received; executing` و پس از پایان نتیجه را چاپ می‌کند. HTTP 401 راهنمای بررسی توکن، HTTP 404 راهنمای بررسی آدرس/شناسهٔ پروژه و HTTP 403 راهنمای بررسی محدودیت هاست دارد. متن پاسخ خطا، هدرها، توکن یا رمزها چاپ نمی‌شوند. پس از دریافت نسخهٔ جدید، فایل Python دانلودشدهٔ قبلی را نیز جایگزین کنید؛ انتشار PHP روی سایت، فایل Downloads ویندوز را به‌روزرسانی نمی‌کند.


## استفاده از شبکه یا VPN فعلی ویندوز و کپی لاگ

در «روش دسترسی به SQL Server»، گزینهٔ «استفاده از شبکه / VPN فعلی سیستم — بدون تغییر اتصال» را انتخاب و تنظیمات را ذخیره کنید. این انتخاب همان `vpn_enabled=false` است و با نسخه‌های قبلی ایجنت نیز سازگار است. اگر در LAN شرکت هستید، اتصال مستقیم استفاده می‌شود؛ اگر بیرون شرکت هستید، ابتدا خودتان VPN را در ویندوز متصل کنید. ایجنت هیچ پروفایل VPN، اتصال یا مسیری را در این حالت ایجاد، حذف، قطع یا وصل نمی‌کند. فیلدهای VPN در فرم پنهان و غیرفعال هستند؛ مقادیر ذخیره‌شده حفظ می‌شوند تا انتخاب اختیاری مدیریت VPN همچنان ممکن باشد، اما مشخصات VPN در حالت شبکهٔ فعلی به ایجنت ارسال نمی‌شوند.

«تست مسیر شبکه تا SQL» فقط دسترسی به پورت سرور SQL را بررسی می‌کند؛ پس از آن «تست اتصال SQL و نمایش ستون‌ها» احراز هویت و SELECT ویو را انجام می‌دهد. پیش‌نمایش و تأیید و زمان‌بندی قبلی حفظ شده‌اند. تغییر حالت اتصال، مانند سایر تغییرات تنظیمات، تأیید قبلی زمان‌بندی را باطل می‌کند؛ پس از تست موفق، پیش‌نمایش جدید را تأیید کنید. کامپیوتر ایجنت در زمان اجرای روزانه باید روشن و مسیر شبکه/VPN آن برقرار باشد.

کنار خروجی، دکمهٔ «کپی لاگ» متن همان خروجی را در Clipboard قرار می‌دهد. اگر مرورگر اجازهٔ Clipboard ندهد، یک فیلد فقط‌خواندنی با متن انتخاب‌شده برای Ctrl+C یا کپی دستگاه نمایش داده می‌شود. این دکمه فقط لاگ را کپی می‌کند و تنظیمات اتصال و رمزها را به خروجی اضافه نمی‌کند.

اعتبارسنجی این تغییر: ۳۶ بررسی PHP، ۹ تست Python، جریان HTTP قبلی پیش‌نمایش/تأیید/زمان‌بندی، و تست مرورگر برای ذخیرهٔ حالت شبکهٔ فعلی، پنهان‌سازی فیلدهای مدیریت VPN، ارسال‌نشدن مشخصات VPN به ایجنت، کپی دقیق لاگ و مسیر کپی دستی. تست مستقیم Python بررسی می‌کند که مسیر فعلی بدون اجرای هیچ subprocess مربوط به VPN به مرحلهٔ SQL می‌رسد. این‌ها جای اتصال واقعی به سرور SQL پروژه را نمی‌گیرند.


## SQL compatibility mode (explicit project setting)

Under «امنیت اتصال SQL», select «بدون الزام رمزگذاری و بدون بررسی گواهی» and save to enable `sql_security=compatibility` for that project. The updated agent uses ODBC `Encrypt=no;TrustServerCertificate=yes` and omits `HostNameInCertificate` in this mode. Verified TLS is still the default for new configurations; invalid mode values are rejected. Changing the mode changes the connection fingerprint and requires a fresh approved preview before daily synchronization. This SQL setting does not change HTTPS authentication with the panel or the selected system-network/VPN mode. Client-side optional encryption does not override encryption enforced by SQL Server. Update the downloaded Python agent before use.
