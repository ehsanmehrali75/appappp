# متن آماده برای تیم فنی تیام

سلام، وقت بخیر.

اتصال به `SplandDB` و خواندن `dbo.FactInventory` با کاربر گزارش‌گیری موفق شد. برای سازگاری کامل با بخش «اتوماسیون استخراج → همگام‌سازی و کپی ستون‌ها دستی» و مسیر خودکار جدید، لطفاً یک خروجی موجودی با مشخصات زیر آماده کنید. ترجیحاً یک View مخصوص گزارش مانند `dbo.vw_MaarkshoInventory` بسازید و نام نهایی را اعلام کنید؛ جدول‌های عملیاتی نیاز به تغییر ندارند.

هر ردیف باید موجودی یک **کد تنوع کالا در یک شعبه/انبار** باشد؛ ترکیب `ProCode + AnbarCode` تکراری نباشد. اگر موجودی در منبع خردتر است، قبل از خروجی در همین سطح تجمیع شود و Joinها موجودی را چندبرابر نکنند.

ستون‌های مورد نیاز:

| نام ستون | توضیح |
|---|---|
| `ProCode` | کد واقعی و یکتای تنوع کالا، از نوع متن؛ صفرهای ابتدای کد حفظ شود |
| `ProDes` | نام/شرح اصلی محصول؛ سایز و رنگ در ستون‌های مستقل باشند |
| `ModelCode` | کد ثابت مدل مادر؛ برای همهٔ سایزها و رنگ‌های یک مدل یکسان باشد و با تغییر نام عوض نشود |
| `Size` | سایز واقعی به صورت متن، مانند `38.5`، `M` یا `2`؛ Free Size فقط برای کالای واقعاً فری‌سایز |
| `ColorCode` | کد ثابت رنگ، به صورت متن |
| `Color` | نام خوانای رنگ |
| `AnbarCode` | کد شعبه/انبار؛ می‌تواند معادل `ShopCode` فعلی باشد |
| `AnbarName` | نام شعبه/انبار؛ می‌تواند معادل `ShopName` فعلی باشد |
| `StockTedad` | موجودی عددی، ترجیحاً `decimal(18,3)`؛ صفر معتبر است و NULL نباشد |
| `NetItem` | در صورت دسترس بودن، قیمت فروش **یک واحد از همان تنوع**؛ مبلغ کل ردیف/فروش نباشد. واحد ریال یا تومان را صریح اعلام کنید |
| `CategoryPath` | در صورت وجود، مسیر دسته‌بندی به صورت `جنسیت/گروه/نوع` مطابق طبقه‌بندی واقعی؛ دادهٔ ناموجود حدس زده نشود |
| `LastUpdateDateTime` | زمان آخرین به‌روزرسانی موجودی؛ منطقهٔ زمانی آن اعلام شود |

ستون‌های فعلی `Category`، `SubCategory`، `ProductType` و `Grade` هم حفظ شوند. لطفاً معنای `Grade` را اعلام کنید؛ فعلاً آن را سایز یا رنگ فرض نکرده‌ایم. اگر قیمت یا مسیر دسته‌بندی موجود نیست، اعلام کنید تا نگاشت اختیاری آن غیرفعال بماند؛ عدد یا دسته‌بندی فرضی جایگزین نشود.

قواعد تطابق: هر `ProCode` در تمام شعب باید به یک `ModelCode`، `Size` و `ColorCode` ثابت مربوط باشد. تنوع‌های یک مدل/رنگ زیر یک محصول جمع می‌شوند، اما SKU واقعی هر سایز حفظ خواهد شد. قیمت یک SKU در شعب مختلف باید قیمت مرجع یکسانی داشته باشد؛ اگر قیمت شعب متفاوت است، این موضوع جداگانه اعلام شود.

در نمونهٔ فعلی، کدهای `86400`، `86403`، `86405` و `86408` همگی شرح `Horizon Fit W` دارند؛ لطفاً مشخصات واقعی مدل مادر، سایز و رنگ این چهار کد را نیز به‌عنوان نمونه بفرستید. از روی نام یکسان یا ترتیب اعداد کد، سایز و رنگ قابل تعیین نیست.

خروجی برای همگام‌سازی روزانه، اسنپ‌شات کامل موجودی شعب مورد توافق باشد. کالاهای صفرموجودی نیز در آن باشند و فیلتر شعب/کالاها اعلام شود. کاربر گزارش‌گیری فقط دسترسی SELECT روی گزارش جدید داشته باشد. لطفاً نام نهایی View، واحد قیمت، منطقهٔ زمانی و ۵ تا ۱۰ ردیف نمونه شامل چند سایز، دو رنگ، دو شعبه و موجودی صفر ارسال کنید.

ممنون.
