# مرکز داده و انتشار پروژه‌ای

ورودی پنل: `/panel/data-hub.php?project=PROJECT_ID`، از صفحه اتصال ChatGPT، تحلیل فروش، سئو و هوش داده و مدیریت وردپرس قابل دسترسی است.

## مسیر هر پروژه

1. کاربر با مجوز همان پروژه یک منبع می‌سازد: نام، منشأ، فروشگاه و انواع دادهٔ مجاز. توکن منبع یک‌بار نمایش داده و فقط هش آن سمت پنل ذخیره می‌شود. هر منبع فقط پروژه و داده‌های تعیین‌شده را می‌نویسد؛ تغییر نقش/رمز/مجوز مالک یا توقف منبع، دریافت بعدی را مسدود می‌کند.
2. وردپرس با افزونهٔ نسخهٔ ۵، CRM با HTTP، یا کاربر با Excel/JSON/CSV داده را وارد می‌کند. ChatGPT هم با `hub_sources` و `save_hub_records` می‌تواند خروجی ابزارهای متصل و مجازش را ثبت کند. اتصال به یک اپ در ChatGPT مجوز دسترسی به بقیهٔ اپ‌ها یا پروژه‌ها ایجاد نمی‌کند.
3. `read_data` منابع `hub:SOURCE_ID:KIND` را می‌خواند. شناخت پروژه و برنامه‌های گزارش API همان منابع را می‌بینند. گزارش API علاوه بر نمونهٔ ردیف‌ها، آمار دقیق فروش تفکیک‌شده و نقص متادیتا را دریافت می‌کند.
4. صفحه‌های تحلیل فروش و سئو نیز کارت‌های همین دادهٔ واقعی را نشان می‌دهند؛ ابزارهای قدیمی حذف نشده‌اند. داده‌های نمایشی قدیمی سئو، شاهد اتصال واقعی نیستند و در مرکز داده استفاده نمی‌شوند. بازطراحی کامل تمام نماهای قدیمی سئو در این تغییر انجام نشده است.

## قرارداد دریافت CRM / فایل

`POST https://maarksho.com/panel/integration_ingest.php`

هدر: `Authorization: Bearer SOURCE_TOKEN` و `Content-Type: application/json`.

```json
{
  "kind": "sales",
  "batch_id": "crm-export-20261019-page-1",
  "complete": false,
  "rows": [
    {"id":"order-123","date":"2026-10-19","grain":"order","currency":"IRR","gross":1200000,"refund":200000,"net":1000000,"orders":1,"status":"completed"}
  ]
}
```

انواع: `products`, `inventory`, `sales`, `posts`, `pages`, `gsc`, `ga4`. هر بسته حداکثر ۱۰۰۰ ردیف/۴ مگابایت. شناسهٔ پایدار ردیف در **همان منبع و نوع** upsert می‌شود. بسته با شناسهٔ تکراری و payload یکسان تکرار نمی‌شود؛ تغییر payload با همان batch_id رد می‌شود. در فایل اکسل شناسه‌ها و SKUهای دارای صفر اول را Text نگه دارید؛ فرمول مجاز نیست. فایل پیش از تأیید ثبت نمی‌شود.

برای فروش `date` میلادی، `grain=order|day`، کد ارز سه‌حرفی و `gross/refund/net/orders` الزامی است. `net=gross-refund` است. هر فروشگاه یک source مستقل داشته باشد. **منابع هم‌پوشان، ارزهای مختلف و جمع روزانه/سفارش با هم جمع نمی‌شوند.** وضعیت cancelled/failed/pending/on-hold/checkout-draft/trash در جمع فروش لحاظ نمی‌شود. مبلغ سفارش ووکامرس شامل اجزای total همان سفارش (از جمله مالیات/ارسال طبق تنظیم سایت) است؛ آن را بدون تعریف یکسان با درآمد خالص محصول مقایسه نکنید.

این مرکز داده، رکوردهای منبع را تجمیع می‌کند و به‌طور خودکار محصول جدید در کتابخانه نمی‌سازد یا موجودی مرکزی/تصاویر باکیفیت را بازنویسی نمی‌کند. تطبیق و ورود به کتابخانه باید از مسیر تأییدشدهٔ واردسازی موجود انجام شود. دریافت incremental است؛ نبود رکورد در یک بسته به معنی حذف محصول، صفرشدن موجودی یا حذف سفارش نیست. `complete` رسید پایان پیمایش منبع است، نه مجوز حذف رکوردهای غایب. در گزارش، تازگی داده و زمان آخرین پیمایش بررسی شود.

## افزونهٔ WordPress نسخهٔ ۵

کد مستقل: `integrations/wordpress/maarksho-crm-sync/maarksho-crm-sync.php`؛ دریافت ZIP قابل نصب از `/panel/wp-crm.php?download_plugin=1` پس از ورود و مجوز wp_crm. جایگزین نسخهٔ قبلی شود؛ دو افزونه همزمان فعال نکنید.

- داخل پیشخوان وردپرس منوی «مارکشو»، آدرس دریافت پنل و توکن source را وارد کنید. نوع داده‌ها باید با source یکسان باشد. توکن‌ها در خروجی صفحه نمایش داده نمی‌شوند.
- محصولات و **تنوع‌ها** جدا با parent_id، SKU، تصاویر، دسته‌بندی، ویژگی‌ها، موجودی و قیمت خوانده می‌شوند. مقدار رنگ مرکب مثل سفید-سبز شکسته نمی‌شود.
- سفارش‌ها از `wc_get_orders`، سازگار با HPOS، بدون اطلاعات شخصی مشتری دریافت می‌شوند. همهٔ وضعیت‌ها خوانده می‌شوند تا تغییر/لغو سفارش نیز به‌روز شود.
- مقالات و برگه‌ها، وضعیت و متادیتای واقعی Rank Math/Yoast دریافت می‌شوند. کلیدهای صحیح `rank_math_title`, `rank_math_description`, `rank_math_focus_keyword`, `rank_math_canonical_url`, `rank_math_robots`, `rank_math_seo_score` استفاده می‌شوند؛ نمرهٔ رتبهٔ گوگل ساخته نمی‌شود. خالی‌بودن meta ممکن است در سایت با قالب افزونه جبران شود؛ داشبورد نقص متادیتا را از رتبهٔ جست‌وجو جدا می‌کند.
- هر tick یک بستهٔ ۵۰تایی و checkpoint پس از رسید موفق پنل. تکرار بسته هزینه/رکورد فروش تکراری ایجاد نمی‌کند. WP-Cron پنج‌دقیقه‌ای به بازدید سایت وابسته است؛ برای اجرای مطمئن، Cron واقعی هاست wp-cron را صدا بزند.
- REST نسخهٔ `maarksho-crm/v1/export?kind=products&page=1&per_page=50` با توکن خواندن جدا، صفحه‌بندی دارد. REST نوشتن به‌صورت پیش‌فرض غیرفعال است؛ مدیر سایت باید صریحاً اجازه دهد. عنوان/توضیح/قیمت/تصویر و SEO با این اجازه قابل به‌روزرسانی هستند. دریافت تصویر فقط HTTPS عمومی و با اعتبارسنجی WordPress است.
- مسیر قدیمی pull_data پنل متوقف شده، چون سفارش‌ها را دوباره به جمع فروش اضافه می‌کرد و تصاویر/موجودی را بازنویسی می‌کرد. مقاله/برگهٔ ساختگی نیز دیگر با بازشدن پنل تولید نمی‌شود. دادهٔ قبلی کاربر خودکار پاک نشده است.

## Google واقعی و روزانه

در مرکز داده، source با `gsc`/`ga4` بسازید. در Google Cloud، Search Console API و Analytics Data API فعال و OAuth Client نوع Web ایجاد شود. Client ID/Secret در فرم خصوصی پنل وارد شوند؛ redirect دقیق:

`https://maarksho.com/panel/google_callback.php`

حساب دارای دسترسی Property/Site، scopeهای فقط خواندن را تأیید می‌کند. GA4 Property ID عددی و Search Console Site دقیق (مثل `sc-domain:example.com` یا `https://example.com/`) لازم است. Refresh token و Client Secret رمزگذاری می‌شوند. در حالت Testing گوگل، محدودیت کاربران تست/انقضای refresh token ممکن است اعمال شود؛ برای استفادهٔ ماندگار تنظیمات OAuth خود گوگل تکمیل شود.

دریافت واقعی: GSC ابعاد date/page/query؛ GA4 ابعاد date/pagePath و sessions/activeUsers/keyEvents/totalRevenue. هر درخواست حداکثر ۱۰۰۰ ردیف. گوگل ممکن است داده را با تأخیر، threshold یا حذف queryهای حساس ارائه کند؛ دادهٔ GSC تضمین تمام queryها نیست. کاربران/نشست‌های صفحه‌ای و میانگین رتبه قابل جمع ساده نیستند. دادهٔ نمایش‌نداده‌شده حدس زده نمی‌شود.

Cron، علاوه بر worker گزارش API قبلی:

```cron
*/5 * * * * /usr/local/bin/php /home/ACCOUNT/public_html/panel/integration_worker.php >> /home/ACCOUNT/private/integrations.log 2>&1
```

worker حداکثر سه صفحهٔ گوگل در هر اجرا، ادامهٔ cursor و refresh روزانهٔ ۷ روز کامل اخیر را انجام می‌دهد. دریافت دستی برای بازهٔ حداکثر ۹۳ روز نیز موجود است. دامنه‌های لازم: accounts.google.com، oauth2.googleapis.com، www.googleapis.com، analyticsdata.googleapis.com. بررسی گواهی فعال است.

## تقویم، ادمین خودکار و ChatGPT برای تمام پروژه‌ها

- روش «ChatGPT» در تنظیمات اتصال تلگرام/اینستاگرام یا فرم مرکز دادهٔ هر پروژه قابل انتخاب است. به سرویس/پروژه/کاربر خاصی hard-code نشده است. مقصد اکانت/کانال در همان پروژه تعیین می‌شود.
- اتصال ChatGPT قبلی برای scope تازهٔ `social.write` باید دوباره تأیید شود. `social_jobs` صف مجاز، `social_plan` پیشنهاد برنامهٔ حداکثر ۳۰ آیتم در **تقویم اصلی با تأیید pending**، `social_create` صف مستقیم برای کاربر دارای مجوز انتشار، `social_claim` دریافت انحصاری کار و `social_ack` ثبت رسید ابزار انتشار هستند.
- برای ادمین خودکار روزانه/هفتگی در «گزارش‌ها و برنامه‌ها»، نوع برنامه را «ادمین خودکار: پیشنهاد برنامه در تقویم» بگذارید، منبع API و منابع فروش/سئو/محصولات را انتخاب کنید. مدل برنامهٔ ساختاریافته می‌سازد و worker آن را در همان تقویم ثبت می‌کند. مجوز calendar و auto_admin هر اجرا دوباره بررسی می‌شود. خروجی نامعتبر، برنامهٔ اجرایی ایجاد نمی‌کند؛ گزارش/مصرف واقعی حفظ می‌شود. هیچ برنامه‌ای تأیید تقویم یا تأیید تصویر را دور نمی‌زند.
- بعد از تأیید تقویم و رسیدن زمان، cron موجود آیتم‌های ChatGPT را به صف همان پروژه می‌برد؛ پست/استوری صف‌شده «ارسال‌شده» حساب نمی‌شود. `social_claim` معمولاً فقط کار due را می‌دهد؛ اگر ابزار خارجی زمان‌بندی را انجام می‌دهد، `schedule_externally=true` برای گرفتن کار آینده استفاده شود و ack برابر `scheduled_external` با رسید زمان‌بندی برگردد. بعد از انتشار واقعی ack برابر published و رسید واقعی لازم است.
- ChatGPT نمی‌تواند با اتصال صرف به پروژه، به اکانت شبکه اجتماعی دسترسی بگیرد یا خودبه‌خود Worker دائمی شود. کاربر باید اپ دارای مجوز ارسال/زمان‌بندی را به ChatGPT متصل کند، یا یک سرویس/Worker واقعی از این ابزارها استفاده کند. بدون آن، برنامه و صف آماده‌اند ولی ارسال واقعی انجام نمی‌شود. نام/مستندات سرویس خاص برای این پروتکل عمومی لازم نیست؛ برای نوشتن adapter مستقیم یک سرویس، API همان سرویس لازم است.
- رسیدها `external_reported` هستند؛ پنل آنها را بررسی مستقل شبکهٔ اجتماعی معرفی نمی‌کند. کار claim‌شدهٔ نامشخص کورکورانه دوباره منتشر نمی‌شود.

## اعتبارسنجی و حدود این انتشار

تست HTTP با پایگاه موقت، upsert فروش/ارز/سطح، scope و جداسازی پروژه، adapterهای گوگل با پاسخ کنترل‌شده، صف/claim/رسید و تقویم با حفظ تأیید، و قرارداد افزونه با doubles وردپرس انجام می‌شود. در مرورگر، XLSX واقعی و چیدمان موبایل بررسی می‌شود. اتصال زنده به WordPress واقعی، Google واقعی و ارسال واقعی Instagram/Telegram نیازمند استقرار، رضایت OAuth و دسترسی اکانت است؛ این موارد با تست محلی یا push گیت‌هاب تأییدشده محسوب نمی‌شوند.

## تست اتصال، بستر پروژه و گزارش تجمیعی

تب «سلامت اتصال‌ها» نوع بستر پروژه، مرجع هر حوزه، تست‌های خواندنی وردپرس/تلگرام/اینستاگرام و آخرین دریافت هر منبع را جدا نشان می‌دهد. تست بومی شبکه اجتماعی هیچ پست آزمایشی نمی‌فرستد و مجوز انتشار را اثبات نمی‌کند. در روش ChatGPT رسید خود ابزار لازم است. تست واقعی SQL تیام باید از ایجنت داخل شبکه انجام شود؛ هاست اشتراکی نمی‌تواند دسترسی شبکهٔ داخلی را حدس بزند. ورودی دستی موجودی ERP همان مسیر پیش‌نمایش/تأیید سیستم مرکزی است؛ ذخیرهٔ شاهد inventory در مرکز داده خودبه‌خود موجودی مرجع را بازنویسی نمی‌کند.

برای پروژهٔ تیام مرجع موجودی/قیمت تیام یا فایل تأییدشدهٔ آن است؛ برای وردپرس مرجع ووکامرس/فایل همان منبع است. محصولات دیگر به مجوز wp_crm وابسته نیستند؛ پروژهٔ تیام با مجوز محصولات نیز منابع محصول دارد. سئو، تصاویر سایت و Google مکمل ERP هستند؛ اطلاعاتی که ERP ندارد خودکار ساخته نمی‌شود.

تب «گزارش تفکیکی و تجمیعی» و ابزار خواندنی `hub_sales_report` گزارش فروش به تفکیک فروشگاه/روز/ماه و جمع کل را برای منابع منتخب تولید می‌کنند. یک ارز و یک سطح داده انتخاب می‌شود و انتخاب دو منبع برای یک فروشگاه رد می‌شود؛ این مانع اصلی دوباره‌شماری CRM/ووکامرس است. `integration_health` نیز وضعیت ضبط‌شدهٔ اتصال و مرجع داده را به ChatGPT می‌دهد. گزارش‌های پیچیده‌تر می‌توانند با خواندن صفحات منابع و ذخیرهٔ تحلیل در save_report تهیه شوند؛ جمع سادهٔ کاربران یکتا، CTR یا رتبه مجاز نیست.

## Composio

منبع مستقل با نوع gsc و روش Composio بسازید، در تب Composio کلید API، Connected Account واقعی، Site و Tool slug همان حساب را تنظیم کنید. کلید رمزگذاری و از خروجی ChatGPT حذف می‌شود. مسیر جدید فقط ابزار خواندنی Search Analytics را اجرا می‌کند و از fallback شبیه‌سازی‌شدهٔ لایهٔ قدیمی استفاده نمی‌کند. خروجی باید date/page/query و متریک‌های معتبر داشته باشد؛ خروجی ناسازگار یا پاسخ ناموفق ثبت نمی‌شود. اسلاگ/ساختار ابزار به نسخه و حساب Composio بستگی دارد؛ خطای واقعی نمایش داده می‌شود و اتصال زنده تا تأیید سرویس موفق محسوب نمی‌شود.

دریافت دستی یک صفحه برای تست موجود است. integration_worker ادامهٔ صفحات را با حداکثر دو بستهٔ Composio در هر اجرا می‌خواند و پس از پایان، روزانه هفت روز اخیر را تازه می‌کند. دادهٔ مستقیم Google و Composio را دو مشاهدهٔ یک Site بدانید؛ آنها را به عنوان دو مجموعهٔ مستقل با هم جمع نکنید. دامنهٔ خروجی لازم: `backend.composio.dev`.

## پوستهٔ جدید تحلیل فروش، سئو و هوش داده

`/panel/insights.php?project=PROJECT_ID&domain=sales|seo|intelligence` پوستهٔ مشترک جدید این سه بخش است. ورود عادی از sale.php، seo.php و نماهای seo_intel پس از همان کنترل دسترسی قبلی به پوستهٔ جدید هدایت می‌شود. نمای کلی، فیلتر تاریخ/منبع، جدول صفحه‌بندی‌شده، گزارش تفکیکی و تجمیعی، اتصال و گزارش تست، و مسیر تحلیل/تقویم هوشمند یکدست هستند. داده‌های نمایشی قدیمی در KPI جدید مصرف نمی‌شوند.

کنترل دسترسی هر دامنه و زیرنماهای هوش داده مستقل است؛ دانستن لینک یا شناسهٔ پروژه دسترسی ایجاد نمی‌کند. JSON خروجی ردیف‌ها صریحاً برای همان صفحه است؛ برای دریافت همهٔ داده‌ها صفحه‌های بعد یا read_data فراخوانی شود.

فرم‌های تخصصی قبلی (اهداف، فروشگاه‌ها، شاخص‌های سفارشی و ابزارهای تخصصی سئو) از تب ابزارها با legacy=1 حفظ شده‌اند؛ همهٔ فرم‌های داخلی قدیمی در این انتشار بازنویسی نشده‌اند. سوابق فروش قدیمی بدون واحد مبلغ/تعریف بازهٔ یکسان به جمع سفارش منابع جدید اضافه نمی‌شوند، اما از بخش فروشگاه‌های ثبت‌شده قابل بررسی و ویرایش هستند.


### Connection reconfiguration and audit safeguards

Each warehouse source has one automated adapter (Google or Composio). Reconfiguring it clears the old adapter and its pagination checkpoints. A configuration revision prevents an in-flight old import, OAuth callback or worker checkpoint from writing into the new configuration. Existing warehouse rows remain intact; once rows exist, changing the configured Search Console site or GA4 property requires creating a separate source to preserve provenance.

Connection tests are tied to the tested settings. Changed settings, tests older than 24 hours and legacy tests without a configuration fingerprint display as requiring a new test. The private fingerprint is never returned by the health API. Project deletion also removes connection tests and adapter checkpoints.

Warehouse pages retain only the requested rows and a bounded document cache while calculating an exact filtered count. Invalid calendar dates, reversed date ranges, non-list batches, boolean record IDs and fractional order counts are rejected. Successful empty Composio search responses are accepted as empty pages, without deleting existing observations.
