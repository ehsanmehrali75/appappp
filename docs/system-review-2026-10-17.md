# بازبینی و اصلاحات ۱۷ اکتبر ۲۰۲۶

بررسی روی مسیرهای مدیریت و پورتال، تطبیق و خروجی وب‌سایت، استودیو جدول سایز، اسکرپر دسکتاپ و ایجنت تیام انجام شد. موارد زیر با دادهٔ آزمایشی بازتولید و اصلاح شدند.

| بخش | ایراد و رفتار اصلاح‌شده |
| --- | --- |
| موجودی و صف کار | موجودی کل معتبر مرجع تشخیص موجود/ناموجود است؛ موجودی آنلاین قدیمی، محصول با موجودی کل صفر را به صف برنمی‌گرداند. |
| تطبیق سایت | دریافت مجدد خروجی سایت، تغییرات محلی عکس، جدول و توضیحات را خودکار آپلودشده حساب نمی‌کند. |
| تأمین مجدد موجودی | غیبت محصول ناموجود از خروجی کامل سایت، رسید انتشار قدیمی را پاک می‌کند؛ بعد از تأمین موجودی، کار لازم پنهان نمی‌ماند. فایل‌ها حفظ می‌شوند. |
| دسترسی عملیات | مجوز تغییرات از نوع عملیات بررسی می‌شود؛ انتخاب یک تب مجاز، دسترسی به عملیات تنظیمات، لندینگ یا تقویم ایجاد نمی‌کند. درخواست‌های مستقیم مجاز به کنترل‌کننده نیز کار می‌کنند. |
| کاربران و بازیابی | افزودن کاربر در یک پروژه، عضویت هم‌نام او در پروژه‌های دیگر را حذف نمی‌کند. بازیابی کامل پشتیبان که کاربران و تنظیمات دسترسی را جایگزین می‌کند، به مدیر اصلی محدود است. |
| عکس رفرنس | مجوز تغییر مرحلهٔ درخواست، پیش از حذف یا جایگزینی فایل رفرنس بررسی می‌شود؛ عملیات ردشده، فایل قبلی را حذف نمی‌کند. |
| برندینگ جدول سایز | پروژهٔ مقصد ذخیره باید با پروژهٔ مجاز صفحه یکی باشد. مقدار صفر حاشیه و گردی حفظ می‌شود و CSS پیش‌فرض، رنگ ردیف‌ها و جهت متن انتخابی را نمی‌پوشاند. |
| اسکرپر دسکتاپ | در نسخهٔ ۲.۱.۱، وجود عنصر خالی به‌معنی آماده‌بودن توضیحات، قیمت و سایر فیلدها نیست؛ دریافت محتوای با تأخیر، در مهلت محدود بررسی می‌شود. |
| ایجنت تیام | نتیجهٔ SQL هنگام خطای موقت ارسال در حافظه نگه داشته و دوباره ارسال می‌شود؛ SQL دوباره اجرا نمی‌شود. دریافت تکراری همان نتیجه، داده را دوباره اعمال نمی‌کند. اشغال موقت قفل، پاسخ قابل‌تلاش مجدد دارد. |

اعتبارسنجی موفق: ۱۲ مجموعهٔ PHP، ۶۴ تست HTTP/ایجنت، ۷۹ بررسی مرورگر پورتال و استودیو، ۱۷ بررسی محتوای با تأخیر اسکرپر، آزمون رابط Qt و ۱۰ سناریوی کامل اسکرپر. این بررسی‌ها شامل درخواست واقعی به PHP/SQLite آزمایشی، ساخت و بازکردن ZIP واقعی، پورتال در عرض‌های ۳۲۰ تا ۱۴۴۰ پیکسل، ذخیره و بارگذاری دوبارهٔ برندینگ و قطع ارتباط ایجنت است. سازگاری با فشرده‌سازی فعال هاست و نبود `array_is_list` نیز بررسی شد. تست‌های مرورگر پورتال و استودیو به CI اضافه شده‌اند؛ تست‌های HTTP جدید نیز در کشف خودکار تست‌ها اجرا می‌شوند.

هیچ تستی روی دیتابیس یا فایل کاربران سایت اصلی اجرا نشده است. اتصال واقعی شبکهٔ داخلی SQL و نتیجهٔ استقرار روی هاست، با تست‌های محلی اثبات نمی‌شود. انتشار در GitHub نیاز به دریافت نسخهٔ جدید روی هاست دارد؛ برای اصلاح اسکرپر و ایجنت نیز فایل اجرایی Python مربوط باید به‌روز شود.
